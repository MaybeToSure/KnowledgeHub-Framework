# 检索、项目上下文与成果回流

## 检索

1. 从用户任务提取主题、对象、时间范围、知识类型和目标用途。
2. 先检索标题、元数据、稳定 ID 和正文，再读取少量最相关原文。
3. 按人工指令、人工锁定知识、用户规则、核心规则、AI 推断的顺序解决冲突。
4. 输出引用的相对路径或稳定 ID，并区分事实、推断和缺口。

## 项目上下文

- 在 `50-Projects/<项目>/项目入口.md` 记录目标、仓库引用、使用的知识 ID 和知识库提交号。
- 代码项目默认位于知识库之外的独立仓库，不在 `50-Projects` 内嵌套 `.git`。
- 使用项目 ID、本地路径、远程地址、默认分支、项目提交号和知识库提交号建立双向追溯。
- 只向项目提供任务所需资料，不复制整个知识库。
- 项目仓库必须能够独立构建；知识库必须能够独立阅读。
- 除非人工明确要求固定聚合多个仓库版本，否则不得引入 Git Submodule。

## 成果回流

- 项目专属实现细节留在项目仓库。
- 可跨项目复用的方法、决策、实验结论和验证证据回流到 `20-Knowledge`、`60-Experiments` 或 `70-Outputs`。
- 回流条目引用项目仓库、提交号和证据位置，不复制完整代码仓库。

## 验收

- 上下文与任务相关且来源可追溯。
- 项目和知识库之间使用稳定引用。
- 回流内容确有复用价值，并保留验证限制。
