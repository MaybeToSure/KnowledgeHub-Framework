# 审核、归档与同步

## 审核

- 检查来源、权威级别、锁定状态、元数据、重复、矛盾、失效链接和过期结论。
- 对事实与来源不一致、无证据的确定性结论标记 `needs-review`。
- 低价值或过期内容移入 `90-Archive`，保留原 ID、归档原因和时间。
- 随手记只有已有可追溯处理结果，或人工明确判定不再处理时，才能移入 `90-Archive/Quick-Captures`。
- 不得让多个执行者同时写同一批文件。

## 同步

1. 读取 `Rules/Core/仓库同步.md` 和相关用户规则，检查 `git status --short`。
2. 运行 `scripts/knowledge-health.ps1`。
3. 暂存变更前确认没有密钥、缓存或错误的大文件跟踪方式。
4. 创建说明变更意图的提交。
5. 使用非破坏性拉取整合远程；冲突时停止、保留双方版本并报告。
6. 推送普通 Git 提交和 Git LFS 对象；禁止强制推送。
7. 验证本地 `HEAD` 与远程分支一致。

## 完整状态

只有普通文件已提交、LFS 对象已上传、本地提交已推送且健康检查没有错误时，才能报告“远程完整同步”。没有配置远程时，只报告本地状态。
