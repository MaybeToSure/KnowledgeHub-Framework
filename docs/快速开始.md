# 快速开始

## 目标

用同一个本地目录连接人工、Obsidian、Codex 和 Git；用户不需要先理解全部规则就能开始记录和整理。

## 从 GitHub 模板创建

1. 在框架仓库页面选择 **Use this template**。
2. 创建一个新的私有仓库，例如 `My-KnowledgeHub`。
3. 创建或选择 `WorkspaceRoot`；默认 `%USERPROFILE%\KnowledgeHub-Workspace`。将仓库克隆到 `<WorkspaceRoot>\KnowledgeHub` 并进入该目录。
4. 运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\tools\setup.ps1
   ```

5. 用 Obsidian 打开根目录。
6. 用 Codex 打开同一目录。

`setup.ps1` 不会推送远程，也不会覆盖已有的 Obsidian 设置；它只补齐缺失配置，并在 `.knowledge/local-config.json` 保存不进入 Git 的设备路径。

## 从 ZIP 创建

将压缩包解压为 `<WorkspaceRoot>\KnowledgeHub`，进入该目录后运行同一条初始化命令。脚本会在缺少 `.git` 时创建 `main` 分支并启用 Git LFS。然后由用户自行创建私有远程仓库并关联。

## 首次验证

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\verify-repository.ps1
```

看到 `VERIFY_OK` 表示目录、Git、Git LFS 和基础安全检查均通过。

## 第一个随手记入口

建立一个明确命名为“云飞随手记”的专用 Codex 任务，并让它以当前 KnowledgeHub 为工作区。普通任务聊天不临时插入随手记。

也可以在 Obsidian 中使用 `Templates/Core/随手记.md`，人工记录默认保存在 `00-Inbox/Human`。AI入口创建的记录位于 `00-Inbox/Human/Quick-Captures`，两种入口都能在 Obsidian 中浏览和编辑。

## 第一个整理任务

把文件放入 `00-Inbox/Human`，然后对 Codex 说：

```text
整理收集箱中的新增资料。保留原始内容，补充元数据和关联；无法确定的继续留在收集箱。
```

整理、汇总、提炼、归档和同步相互独立，只有明确点名的动作才执行。完整边界见 `Rules/Core/随手记.md`。
