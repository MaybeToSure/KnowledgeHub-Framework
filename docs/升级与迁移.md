# 升级与迁移

## 所有权边界

| 路径 | 默认所有者 | 更新行为 |
| --- | --- | --- |
| `.agents/skills/knowledge-hub` | 框架 | 未被用户修改时更新 |
| `Rules/Core` | 框架 | 未被用户修改时更新 |
| `Templates/Core` | 框架 | 未被用户修改时更新 |
| `tools` | 框架 | 未被用户修改时更新 |
| `Rules/Local` | 用户 | 永不覆盖 |
| `Templates/Custom` | 用户 | 永不覆盖 |
| 编号知识目录、`.obsidian` | 用户 | 永不覆盖 |

## 更新步骤

1. 单独克隆或下载新版本框架。
2. 在个人知识库中运行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\tools\update-framework.ps1 `
     -FrameworkSource <新版本框架目录>
   ```

3. 查看脚本输出中的 `updated`、`added` 和 `conflicts`。
4. 人工处理冲突；脚本不会覆盖已修改文件。
5. 运行 `tools/verify-repository.ps1`。
6. 审阅 Git diff 后再提交。

升级到 `0.3.0` 时，在更新脚本之后再运行一次 `tools/setup.ps1`，用于补齐随手记收件箱、摘要和归档目录；它不会覆盖现有 Obsidian 设置或用户资料。

## 回退

更新前先提交当前知识库，或者建立临时分支。更新工具不删除旧文件；如果需要恢复，可使用普通 Git 历史回退单个框架文件。

## 版本策略

- 补丁版本：规则措辞、脚本修复、兼容性修正。
- 次版本：新增模板、工作流或可选工具，保持数据目录兼容。
- 主版本：可能需要人工迁移的目录或元数据契约变化。

框架当前不会自动联网或自动更新，避免在用户不知情时改变知识库治理行为。
