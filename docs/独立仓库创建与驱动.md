# 独立仓库创建与驱动

## 一句话规则

课程、工程、实验、研究、写作或其他持续性任务，只要需要独立交付、独立版本历史或独立权限，就建立一个位于 KnowledgeHub 之外的 Git 仓库。默认由 Codex 根据自然语言创建；人工也可以手动创建，但两条路径必须满足同一份仓库契约。

## 谁负责什么

| 参与者 | 默认职责 | 权限边界 |
| --- | --- | --- |
| 人工 | 提出目标、审核结构、修改任何内容、决定公开或删除 | 最高权限 |
| Codex | 判断类型、创建骨架、登记知识库、组装上下文、校验和维护 | 在人工目标与仓库规则内自治 |
| Obsidian | 人工阅读、写笔记、修订知识库入口 | 不直接承担代码构建 |
| Git / GitHub | 本地版本历史与可选远程协作 | GitHub 不是唯一数据备份 |

“默认由代理创建”不是把所有权交给代理，而是让重复步骤稳定执行。创建 GitHub 仓库、首次推送、公开发布和删除等外部或高风险动作，必须由自然语言明确授权。

## 什么时候建立独立仓库

满足任一条件就应建立：

- 有可运行代码、构建产物、测试或专属依赖。
- 有明确起止、交付物、验收标准或单独版本历史。
- 需要单独分享、授权、发布或归档。
- 实验包含脚本、原始数据、处理过程和可复现结果。
- 课程需要持续积累练习、作业、小项目或课程专属资料。

只有一篇笔记、一个来源、一个可复用知识点或短期想法时，先放进 KnowledgeHub，不急于建仓库。不确定时直接问 Codex：“这个任务是否值得建立独立仓库？请说明判断并按推荐方案处理。”

## 默认路径和类型映射

独立仓库默认创建在 KnowledgeHub 的同级目录。若 KnowledgeHub 位于 `D:\GitHub\KnowledgeHub`，仓库 `analog-electronics` 默认位于 `D:\GitHub\analog-electronics`。

| 工作类型 | 仓库示例目录 | KnowledgeHub 登记位置 |
| --- | --- | --- |
| 课程 Course | `notes/`、`exercises/`、`projects/` | `40-Courses/<仓库名>/entry.md` |
| 工程 Engineering | `src/`、`tests/`、`docs/` | `50-Projects/<仓库名>/entry.md` |
| 实验 Experiment | `protocols/`、`data/`、`results/` | `60-Experiments/<仓库名>/entry.md` |
| 研究 Research | `sources/`、`notes/`、`analysis/` | `50-Projects/<仓库名>/entry.md` |
| 写作 Writing | `sources/`、`drafts/`、`outputs/` | `70-Outputs/<仓库名>/entry.md` |
| 通用 Generic | `docs/`、`work/`、`outputs/` | `50-Projects/<仓库名>/entry.md` |

## 推荐入口：用自然语言驱动 Codex

不需要先切换“项目经理”“程序员”等角色，也不要求记命令。直接说明工作名称、类型、远程意图和目标；Codex 调用知识库内的 `knowledge-hub` Skill 并选择所需工作视角。

```text
为“模电原理”创建独立课程仓库，仓库名 analog-electronics，使用默认本地路径；
在 KnowledgeHub 建立课程入口，暂不创建远程仓库。
```

```text
创建名为 ch583-uart-lab 的实验仓库，并创建我账号下的 GitHub 私有仓库；
把知识库中与 CH583、UART 有关的必要上下文登记进去，但先不要推送。
```

```text
我准备做一个新的工程任务。先判断是否值得建立独立仓库；如果需要，
按推荐结构创建、登记到 KnowledgeHub、完成本地验证，并把所有路径和待确认项告诉我。
```

Codex 在信息明确时直接执行；只有仓库名、路径、类型或外部远程意图会实质改变结果时才补问。未明确说“创建 GitHub 私有仓库”时，默认只创建本地仓库；未明确说“推送”时，不执行推送。

## Codex 实际执行流程

1. 判断是否需要独立仓库，并归类为 Course、Engineering、Experiment、Research、Writing 或 Generic。
2. 确定展示名称、ASCII 仓库名、本地路径和远程模式。
3. 调用 `tools/new-work-repository.ps1` 创建仓库骨架和初始提交。
4. 在 KnowledgeHub 对应目录创建入口，写入稳定 ID、本地路径、远程地址和双方修订号。
5. 只组装当前任务需要的知识上下文，不复制整个知识库。
6. 检查两个仓库的状态；分别审核、分别提交。只有得到明确指令时才推送。

本地课程仓库示例：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\new-work-repository.ps1 `
  -Name "模电原理" `
  -RepositoryName analog-electronics `
  -Type Course
```

明确创建 GitHub 私有远程的示例：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\new-work-repository.ps1 `
  -Name "CH583 UART 实验" `
  -RepositoryName ch583-uart-lab `
  -Type Experiment `
  -RemoteMode GitHubPrivate `
  -GitHubRepository <owner>/ch583-uart-lab
```

脚本不会覆盖非空目录，不允许把新仓库建在 KnowledgeHub 内，不会自动推送。GitHub 模式只创建私有仓库并添加 `origin`。

## 人工手动创建

人工可以直接创建，适合需要自定义骨架或暂时不使用 Codex 的情况：

```powershell
New-Item -ItemType Directory D:\GitHub\my-work
git -C D:\GitHub\my-work init -b main
```

然后至少补齐：

- `README.md`：目标、边界、开始方式。
- `AGENTS.md`：代理协作规则和人工最高权限。
- `work.yaml`：稳定 ID、类型、知识库路径、入口和修订号。
- 与类型相符的工作目录。
- KnowledgeHub 中对应的 `entry.md`（正文标题仍可使用中文）。

手工完成后可直接说：

```text
我手动创建了 D:\GitHub\my-work。请按 KnowledgeHub 的独立仓库契约审核，
补齐缺失文件，登记到知识库，但不要创建远程或推送。
```

## 完成标准

一次创建只有同时满足以下条件才算完成：

- 新目录是独立 Git 仓库，默认分支为 `main`，有可审查的初始提交。
- 存在 `README.md`、`AGENTS.md`、`work.yaml` 和类型对应目录。
- 仓库不位于 KnowledgeHub 内部。
- KnowledgeHub 对应区域存在入口，记录稳定 ID、路径和修订号。
- 两个仓库分别检查状态，未混入无关改动。
- 交付结果明确列出本地路径、远程状态、知识库入口、提交号、验证结果和剩余风险。

创建完成不等于任务完成。后续由 Codex 在独立仓库中实现工作，在 KnowledgeHub 中调阅输入和回流可复用成果。
