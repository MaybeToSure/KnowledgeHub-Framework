# 工作区总览规则

## 定位

- Obsidian 可以把 `WorkspaceRoot` 作为 Vault，从同一界面浏览 KnowledgeHub 和受管理项目仓库。
- `_Dashboard/工作区总览-自动生成.md` 是事实展示层，不是新的资料权威；真实知识和项目文档仍保存在各自仓库。
- `_Dashboard/工作区总览-手动维护.md` 是人工意图展示层，与自动生成页采用相同对象、不同维护方式的命名。
- 第一版只维护一个全局总览，不预设多套视角。

## 生成依据

Codex 运行 `tools/update-workspace-overview.ps1`，只使用这些事实：

- `.knowledge/local-config.json` 中的工作区和仓库根目录。
- 独立仓库顶层 `work.yaml` 的 `id`、`name`、`type`、`status`。
- 仓库 `README.md`、受 Git 跟踪的 Markdown 和最近 Git 提交。
- KnowledgeHub 随手记收件箱中的 Markdown 数量。

没有 `work.yaml` 的目录不自动纳入；缺失字段显示“未登记”，不得由 AI 猜测。

## 所有权

- `工作区总览-自动生成.md` 必须带有 `generated: true` 和固定 `generator` 标记，工具只覆盖符合标记的文件。
- `工作区总览-手动维护.md` 由人工拥有，生成器只在缺失时创建，之后永不覆盖。
- 生成总览不得修改项目文档、知识条目、随手记、Git 状态或聊天服务内容。

## 更新时机

- 人工明确说“更新工作区总览”时。
- 新建、登记、归档仓库后。
- 整理一批随手记或完成重要项目工作后。
- 不要求常驻后台或定时任务。
